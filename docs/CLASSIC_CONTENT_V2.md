# Classic content v2 — editorial and migration handoff

Reviewed for this implementation on September 5, 2026. This is an editorial selection, not evidence of audience enjoyment or recognition. The production draw pool contains **72 newly written lines, 36 new voice-playable directions, and 6 coherent packs**. No creator audio/video or unresolved quotation enters the application. None of these lines asks the judge to imitate a creator's voice.

The choice is confession comedy: a specific mistake, an indefensible explanation, and a final detail that changes the situation. Adult settings add profanity, sexual embarrassment between adults, bodily humor, and more outrageous admissions. An editorial pass removed eight weaker abstract declarations and random-object jokes before handoff. The remaining lines use familiar online speech and meme structures but are not attributed to real people. An originality review here is not a guarantee that nobody has independently made a similar joke.

The `everyone`, `teen`, and `mature` values are actual catalog/database ratings. Clean means no deliberate profanity, explicit sex, or bodily gross-out jokes; it is a host playlist descriptor, not a certification for every child. Spicy includes embarrassing social behavior and sharper jokes. Mature explicitly opts into adult humor/strong language. Selecting Mature permits all lower levels; selecting Spicy never permits Mature. Clean is the default for missing inputs and newly generated Daily rounds. Sixty lines remain Free/rotating, including 25 Mature lines.

`GET /api/prompts/random` accepts `maxRating=everyone|teen|mature`, `exclude` (line slugs/UUIDs), and `excludeEnergy` (direction slugs/UUIDs). Both bundled and database selection enforce the same rating and retirement policy. Canonical submission resolution independently verifies the actual stored rating against the submitted `maxRating`. A copied or forged line body does not replace canonical lookup. An omitted rating never grants Mature access. The filter is an explicit choice, **not age verification**. Launch still needs the owner's age policy, account/consent UX, locale requirements, and terms review; no production rollout is implied by the local opt-in.

Recent exclusions do not relax the audience filter. A fully exhausted safe line pool produces `NO_PROMPTS` so the caller can deliberately cycle its recent history. Direction exclusions relax only within compatible directions when every direction has been seen. Multi-beat emotional directions require at least eight spoken words; difficulty restrictions remain enforced. All 72 lines fit the existing 180-character catalog/database limit and have at least one valid pairing. Directions are audible tasks: pauses, tone, restraint, rhythm, or an emotional turn. No visual pose, camera action, accent, costume, or shouting is necessary.

## Historical compatibility and deployment

- `src/data/legacy-content.ts` freezes the original 120 lines, 48 directions, and 12 pack definitions. ID lookups include those exact strings; new draws use only the v2 pool. Bundled Daily dates before September 5, 2026 retain their original deterministic pair.
- Line/direction identities start with `v2-`. Changed line text never overwrites a pre-v2 slug or database UUID. Six existing pack slugs keep their entitlement class while receiving new presentation/copy; other packs leave discovery.
- **014** adds the real `mature` enum and `draw_enabled` columns. **Commit it before 015.** PostgreSQL does not permit use of a newly added enum value inside the same transaction that adds it.
- **015** inserts 72 lines and 36 directions and retires the explicit old draw lists. It does not delete prompts, archive history-visible rows, update old bodies/instructions, replace challenge references, modify scored takes, or recalculate results. New rows use insert-on-conflict-do-nothing; applying the content block again does not republish moderated v2 rows.
- Existing published rows with `draw_enabled=false` remain available to authorized historical/challenge/Daily joins. A new Classic submission of a retired line/direction fails with `PROMPT_RETIRED`. Existing challenge admission and current Daily pair validation remain authoritative; retired content does not bypass authorization or entitlements.
- `ensure_daily_challenge` returns an existing canonical slot before looking for current draw content. It leaves the precomputed horizon unchanged. Newly generated slots draw only active Clean lines from active Free/rotating packs and compatible active directions. A pre-existing Spicy Daily may still need Spicy opt-in; never silently swap its competitive prompt.
- Fresh-install `supabase/seed.sql` retains historical baseline identities, inserts the same exact v2 block as 015, and marks old draws retired. Existing environments require **the additive migrations**, not merely a new seed. Ship those migrations and the app together; the app expects the new columns. No production migration was run in this task.

## Mature publication hold and saved receipt follow-up

Migration **016** (`202609050016_mature_private_boundary.sql`) keeps Mature recordings private until a separate public age/audience policy is approved. Private play and existing authenticated challenge participation remain available. The database derives a sticky `mature-content` marker from the canonical prompt independently of submitted client preferences. It blocks public and unlisted visibility and attaching a public share asset, including raw trusted writes that bypass the checked visibility RPC. Later rating downgrades or moderation-label rewrites do not erase the original adult receipt restriction. Escalating a previously non-Mature prompt to Mature privatizes its associated takes. Unrelated historical public non-Mature recordings and all historical scores remain unchanged.

The publishing API checks rating before calling moderation; a moderation approval cannot override the age/audience hold. Public share reads independently reject Mature/sticky receipts before signing recording URLs. Owner-only playback/history are still private. Local downloads of a player's own share image are not publication through Delivery.

If any Mature recording already has `share_asset_path`, migration 016 fails with a specific instruction to remove the object through the Storage API and then clear its pointer. SQL cannot revoke an already public Storage object by dropping its pointer. No such cleanup or production migration was performed here. Applying 014, 015, and 016 in order before enabling the new app prevents this situation on first rollout. The same explicit cleanup is required if an operator tries to reclassify a prompt with existing share objects to Mature.

`persistDelivery` can now receive canonical `contentRating`, writes the original rating into score evidence, and adds the Mature marker before insert; the database trigger is a separate backstop. The authenticated account history endpoint now returns canonical/receipt rating, saved rubric version, numerical scoring version, provider-derived result source, coaching, highlights, and validated supplemental Scribe word timings. The judged transcript remains the accuracy transcript. Unknown historical rubrics receive `legacy-unversioned` compatibility rather than an invented modern scale. Historical unlisted visibility remains labeled unlisted.
